# Forge.Rust.LSP

A central repository for all Forge language servers — the Forge equivalent of
Zed's `extensions/` directory. Each language is a **self-contained extension
package** (one folder) that declares its own metadata and ships a native
language server binary.

Because this repo is public, Forge installs can download server binaries
directly from GitHub Releases with no auth or rate limits.

## How it works

- **One folder per language** (`Json/`, `ForgeFlow/`, `Typescript/`, `CSharp/`,
  ...). Each folder contains:
  - `forge-extension.toml` — package metadata (id, name, version, language,
    server binary + args).
  - a Cargo crate producing the server binary. Two styles:
    - Hand-rolled Rust LSP over stdio — `Json/` and `ForgeFlow/` implement the
      language in Rust (parser + LSP), the mirror image of Forge's client.
      `Json/` is the reference for framing/handshake/diagnostics; `ForgeFlow/`
      is the reference for a parser-driven DSL server (see its `usage.md`).
    - Thin proxy over a shared `common/` crate (`forge-lsp-proxy`) for engines
      that already exist (rust-analyzer, tsgo, clangd, ...).
- **`forge-registry.json`** — generated by `tools/registry-gen`: the canonical
  index Forge fetches to discover packages and pick the right release asset for
  the current platform.
- **GitHub Actions** (`.github/workflows/build-release.yml`) — on a `v*` tag it
  builds every package for Windows/macOS/Linux, zips each binary as
  `forge-lsp-<lang>-<platform>.zip`, regenerates the registry, and attaches
  everything to the release.

Forge fetches the release, reads `forge-registry.json`, and lazily downloads +
caches the matching server binary when a user opens a file of that language.

## Adding a language

1. Add a folder with `forge-extension.toml` + a Cargo crate for the server.
2. Tag a release (`vX.Y.Z`); CI builds, packages, and publishes it.
3. The new entry appears in `forge-registry.json` for every Forge install —
   no app update needed.

## Layout

```
Forge.Rust.LSP/
  Json/                    # JSON language server (hand-rolled reference package)
    forge-extension.toml
    src/main.rs
  ForgeFlow/               # ForgeFlow DSL (hand-rolled Rust parser + LSP)
    forge-extension.toml
    src/main.rs
    usage.md               # usage + implementation + app-wiring guide
  tools/registry-gen/      # scans packages -> forge-registry.json
  forge-registry.json      # generated index (committed for reference)
  .github/workflows/build-release.yml
```

## Local build

```sh
cargo build --release                  # build all server packages
cargo run --release -p forge-registry-gen   # regenerate forge-registry.json
```

## Smoke-test a server locally

The request must be `Content-Length`-framed (a bare JSON line makes the server
exit silently):

```sh
printf 'Content-Length: 75\r\n\r\n{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"capabilities":{}}}' |
  target/release/forge-lsp-json
```

Expect a `Content-Length`-framed capabilities response. Wrapper proxies need
their engine present (or downloadable) — they print progress to stderr.
